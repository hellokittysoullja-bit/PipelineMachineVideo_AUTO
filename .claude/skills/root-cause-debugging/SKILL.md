# Root-cause debugging

Основа — `systematic-debugging` (obra/superpowers, MIT), приведённый к
опыту этого репозитория. Он уже подтверждён им на практике: и потерянный
PHRASE LOCK из-за `[sfx:]`, и пустой индекс каталога Мет, и пул, который
«умирал» при отсутствии ключа Pexels, находились только ЗАПУСКОМ, а не
чтением.

**Закон: без найденной причины — никаких правок.** Правка симптома —
провал, даже если тест позеленел.

## Фаза 1. Расследование (до любой правки)

1. Прочитать ошибку и трассу целиком — часто там уже стоит ответ.
2. **Воспроизвести** стабильно, минимальным запуском. Не воспроизводится —
   это отдельная задача, догадки не чинят.
3. Что менялось: `git log`/`git diff`, версии ML-стека, флаги реестра
   (`media_plan/feature_flags.json`), наличие `.env`/ключей.
4. Многокомпонентный путь (источник → пул → гейты → рендер): поставить
   печать/замер на КАЖДОЙ границе и найти стадию, где значение стало плохим.
   Так и нашли главное здесь: дамп пула по стадиям, а не «гейты строгие».
5. Проследить плохое значение назад до источника, а не до места, где
   удобно заткнуть.

## Фаза 2. Образец

Найти рабочий аналог в этом же репозитории (соседний источник, соседняя
ветка фото/видео), прочитать **целиком**, перечислить различия. Асимметрия
фото/видео — самый частый корень здесь (7 случаев в CLAUDE.md).

## Фаза 3. Гипотеза

Одна формулировка: «причина X, потому что Y». Менять **одну** переменную.
Не сработало — новая гипотеза, а не ещё одна правка сверху.

## Фаза 4. Исправление

1. Сначала падающий тест на РЕАЛЬНЫХ данных (фикстура — настоящий ответ, не
   синтетика, см. `tests/fixtures/`).
2. Одна правка. Снести `__pycache__`, снять правку — тест обязан упасть
   (контрольный прогон), вернуть — зелёный.
3. Спросить: **какие ещё места устроены так же?** (`grep` по шаблону, а не
   по имени). Тот же корень часто бьёт в 3-5 местах.
4. **Три неудачные правки подряд → стоп.** Это признак неверной модели
   причины: вернуться в фазу 1, спуститься на уровень ниже по иерархии
   источников истины (`av-ground-truth-check`), при необходимости спросить
   пользователя одним вопросом с вариантами. Правило коммуникации №4
   CLAUDE.md («три попытки → пиши») — то же самое.

## Красные флаги — стоп, вернуться в фазу 1

«Быстро поправлю, потом разберусь» · «попробую поменять X» · «сразу
несколько правок» · «тест не буду писать, проверю руками» · «наверное,
это X» · «не до конца понимаю, но может помочь» · «ещё одна попытка» после
двух неудач.

## Отговорки

| Отговорка | Реальность |
|---|---|
| «Баг простой» | У простых багов тоже есть причина; процесс занимает минуты |
| «Горит» | Угадывание медленнее. Платные вызовы сжигаются от угадывания |
| «Сначала попробую» | Первая правка задаёт направление всем следующим |
| «Тест позеленел» | Зелёный без контрольного прогона может быть зелёным по построению |

## Чего скилл НЕ делает

Не заменяет `deep-audit` для готового ролика (там свои оси, посекундная
сверка) и не разрешает платных вызовов «для диагностики» без слова
пользователя (ЧАСТЬ 1 CLAUDE.md).
