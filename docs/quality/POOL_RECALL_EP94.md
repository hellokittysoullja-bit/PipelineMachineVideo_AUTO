# Этап 0: есть ли нужный кадр в пуле и где он теряется (эпизод 94, 24.09)

**Метод.**
- Прогон харнесса в режиме «только пул» (`SELECTION_POOL_ONLY=1`, без скачиваний и без судьи).
- Пул каждого слота записан вместе с кандидатами, которых выбросил фильтр, и причиной (`removed`), с порядком до фильтра.
- Длительности слотов восстановлены (`pool_recall.base_slot_durs`): без кадра время слота уходит следующему, и фильтр длины видео иначе резал бы по раздутой длительности.
- Для каждого слота и вида размечено объединение первых 10 четырёх порядков:
  - как сейчас;
  - запросы секции последними;
  - каскад по брифу;
  - каскад по брифу без списка запретов.
- Разметка: 2 — точный кадр, 1 — годная замена, 0 — брак. 17 листов, 429 плиток.

**Предел.** Разметка — глаза Claude, не владельца. «Лучшее в пуле» — лучшее среди размеченного, то есть оценка снизу. Эпизод один и короткий (9 слотов).

Файлы: `pool_recall_ep94/index.json`, `labels_claude.json`, `labels_spec.py`; листы — `python scripts/pool_recall.py sheet`.

## Где теряется точный кадр

Точный кадр стоял в первой двадцатке у слотов 4, 5, 6. Проверка мира, добавленная последней (прогон judge7), заменила все три на более слабые:

| слот | прогон judge6 | judge7/judge8 |
|---|---|---|
| 4 «Рыцарь падает в грязь» | упавший рыцарь на турнире (2) | рыцарь, стоящий в лесу (1) |
| 5 «Конница мчится…» | гравюра битвы (2) | фэнтези-всадник с флагом (брак) |
| 6 «Он не поднимается» | рыцарь, сидящий в траве (1) | рыцарь поправляет доспех (0) |

Причина:
- проверка мира бинарна и отклоняет кадр за зрителей на фоне;
- по своему же замеру она пропускает только 3–4 годных кадра из 7.

**Вывод:** потеря на ВЫБОРЕ, а не на поиске.

## Видео

- **Поиск по подписям.** Во всех 2 403 роликах пулов нет ни падающего рыцаря, ни стрелы, бьющей в доспех. Есть:
  - спортивная стрельба из лука — 60+ роликов;
  - 3D-мультфильмы про рыцарей;
  - замки;
  - реконструкции (часть выброшена списком запретов: «medieval parade with knights in armor», «reenactment with knights parade»).
- **Итог.** Ответ на «где видео со стрелой»: в бесплатной видео-выдаче по этим запросам такого ролика нет.

## Что это меняет в плане

1. **Проверка финалистов идёт первой.** По числам она теряет больше, чем поиск: 3 слота из 5 с точным кадром.
2. **Бинарная проверка мира уходит** в первую очередь. Нарушение на фоне — штраф, а не отказ.
3. **Лестница замен** (спецификация + ступени поиска) нужна там, где точного кадра нет: 4 фото-слота из 9 и видео.
4. **Каскад по одному брифу** не доказал пользы. Проверяется каскад по тексту ступеней.
5. **Список запретов** на этом эпизоде нейтрален. Решение — после других эпизодов, а не по одному.

## Проверка финалистов по пунктам — замер (24.09)

**Стенд.** Те же 223 размеченных фото-кадра, по 10 первых каждого слота в порядке каскада. Модель — qwen/qwen3.7-plus. Команда — `python scripts/pool_recall.py bench ... --reasoning off --grid --world --caption`.

Как выбирается кадр слота в каждой схеме:
- **«как в пайплайне»**: сетка оценивает десятку, её 5 лучших проходят проверку по пунктам, решает уровень проверки, потом сетка;
- **«сейчас»**: сетка, затем бинарная проверка мира.

| схема | лучший доступный кадр взят | брак на экране |
|---|---|---|
| только сетка | 5 из 9 | 4 |
| сетка + бинарная проверка мира (было) | 4 из 9 | 4 |
| проверка по картинке, без подписи | 6 из 9 | 3 |
| **проверка с подписью источника (стало)** | **8 из 9** | **1** |

- **По слотам** «было» `[2,0,2,0,1,1,0,1,0]` → «стало» `[2,0,2,1,2,1,2,1,1]`: ни один слот не хуже.
- **Повтор** без кэша проверки, только по 5 финалистам: выборы те же, 8 из 9.

| по кадрам | новая проверка | бинарная проверка мира |
|---|---|---|
| брак принят за точный кадр | 0 из 157 | — |
| брака пропущено | — | 88 из 157 |
| годных отклонено | 6 из 70 | 14 из 70 |

**Подпись источника решила три промаха проверки по одной картинке.** Модель не видела на снимке того, что прямо написано в подписи:
- «moroccan horsemen perform a tbourida» — принято за средневековую конницу;
- «fish shaped metal keychain» — принято за маленький клинок в пальцах;
- «drone shot of a man lying on dry soil» — принято за упавшего рыцаря.

**Цена.**
- С рассуждением и картинкой 1024 px — ~540 токенов баланса за кадр, 30–70 с на вызов, пустые ответы на лимите выхода.
- Без рассуждения, 512 px, с подписью — ~340 за кадр.
- Слот хука (сетка + 5 проверок) — ~4 тыс.; 25 платных слотов — ~100 тыс.

**Пределы.**
- Разметка — глаза Claude.
- Эпизод один; видео не мерились.
- Промах слота 1: годная замена (кинжал в траве) не вошла в пятёрку сетки. Проверка не может выбрать кадр, которого ей не показали.

## Живой прогон judge9 (новый код, настоящий путь отбора) — результат смешанный

Лист: `docs/refactor/sheets/ep94_verify.jpg`. Сравнение с judge8 («сетка + бинарная проверка мира»), глазами Claude:

| изменение | слоты |
|---|---|
| лучше | #5 — вернулся точный упавший рыцарь; #6 — всадники вместо фэнтези-рыцаря |
| хуже | #4 — наконечники копий вместо пластин доспеха; #9 — «человек лежит на сухой земле» |
| примерно так же | остальные |

Стенд обещал 8 из 9, живой прогон этого не повторил. Причины измерены.

1. **Шум модели на пограничных кадрах.** Кадр «drone shot of a man lying on dry soil» с той же подписью и той же картинкой получал в разных вызовах то «не тот предмет, не из мира», то «близкая замена». Между двумя прогонами без кэша расходится 9 ответов из 39 (23%). Две совпавшие серии на стенде устойчивости не доказывают.
2. **Финалистов отбирает шумная сетка.** Если сетка пересобрана и спрошена заново, точный кадр может не попасть в её пятёрку — тогда проверка его не увидит. В одной серии стенда так выпал точный кадр слота 4.
3. **Прогон шёл по старому плану фраз (v1), без замен.** Латную перчатку проверка отвергла как «не тот предмет», хотя в плане v2 она прямо указана ступенью замены.
4. **Ссылки Pixabay на картинки отвечают 429** после тысяч скачиваний превью за короткое время. Так случилось на замерах. Провалы превью внутри каскада сейчас не считаются, поэтому потери в живом прогоне не измерены.

**Попытка ужесточить «близкую замену»** («тот же род предмета, не просто человек») измерена и откатана. Сравнение оказалось недействительным: из-за 429 не скачались точные кадры слотов 4 и 6. Менять замеренное поведение без числа нельзя.

**Что делать дальше, по порядку:**
1. Считать провалы превью в каскаде по источникам; ограничить скорость скачивания для каждого хоста.
2. Финалисты = пятёрка сетки ∪ тройка каскада, чтобы точный кадр не выпадал из-за шума сетки.
3. Устойчивость ответа на пограничных кадрах — повторный вопрос только при расхождении «close/no» с сеткой.
4. Прогон с планом v2 (замены в проверке).
5. Разметка владельца вместо разметки Claude.
