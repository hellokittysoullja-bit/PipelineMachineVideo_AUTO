# Запуск на видеокарте (RTX 4090, RTX 6000 Ada)

Ветка `claude/generator_gpu`. Что именно изменено — в `CLAUDE.md`, раздел «Ветка под видеокарту».

**Модели зрения в этой ветке — только Qwen3-VL** (Embedding-8B и Reranker-2B, решение владельца 29.09). Им нужна видеокарта CUDA с памятью от 24 ГБ: сами модели занимают ~20 ГБ. На T4 (16 ГБ) ветка не работает, для неё есть CPU-ветка.

## 1. Окружение

```bash
git clone <адрес репозитория> && cd PipelineMachineVideo_AUTO
git checkout claude/generator_gpu
python -m venv .venv && . .venv/bin/activate
pip install -r requirements.txt
pip install torchvision   # та же версия CUDA, что у torch; нужна процессору Qwen3-VL
```

## 2. PyTorch с CUDA

```bash
python -c "import torch; print(torch.cuda.is_available(), torch.cuda.get_device_name(0))"
```

Должно напечатать `True` и имя карты. Если `False` — поставить сборку torch с CUDA по команде с pytorch.org для своей версии CUDA.

## 3. ffmpeg с NVENC и drawtext

```bash
sudo apt-get update && sudo apt-get install -y ffmpeg
ffmpeg -hide_banner -encoders | grep nvenc      # должен быть hevc_nvenc
ffmpeg -hide_banner -filters | grep drawtext    # нужен для титров и плашек
```

Если в сборке ffmpeg нет NVENC, клипы кодируются прежним libx264 (`CLIP_ENCODER=auto` проверит это сам).

## 4. Ключи

Скопировать `config.example.env` в `.env` и вписать свои ключи. Файл `.env` остаётся на машине, где идёт рендер, — учитывайте это на арендованном сервере.

## 5. Калибровка порогов — ОБЯЗАТЕЛЬНА, один раз

```bash
python scripts/calibrate_vision.py            # 5–15 минут, веса (~20 ГБ) скачаются сами
```

Без этого шага рендер откажет ещё до первых платных вызовов и напечатает эту же команду. Пороги гейтов выставляются по золотому набору из git, по тому же правилу, что было у SigLIP2: ноль потерь годных и терпимых кадров. Итог печатается числами (сколько брака ловит каждая ось). Смена модели или её разрешения потребует калибровки заново — рендер скажет об этом сам.

Замер качества каскада против прежней SigLIP2 (только там, где лежит запись эпизода 94):

```bash
python scripts/cascade_model_eval.py --freeze temp_selection_freeze/94_dagger_test
```

## 6. Разовая подготовка ради скорости

1. **Зеркало карточек Мет** (один раз, ~2 часа, можно оставить на ночь; прерванная сборка продолжается с места обрыва):

   ```bash
   python scripts/museum_sources.py mirror-met            # окно эпохи канала
   python scripts/museum_sources.py mirror-met --refresh  # раз в месяц
   ```

   Без зеркала Мет — до 3000 запросов на эпизод при скорости 1–5 в секунду.

2. **Квота Pexels.** Бесплатный ключ — 200 запросов в час, а эпизод на 70 слотов делает больше. Когда отбор идёт минуты, а не часы, квота кончается посреди прогона, и поиск Pexels в оставшихся слотах сужается. Pexels бесплатно поднимает лимит по запросу через форму на сайте.

3. **Упреждающий отбор** ВЫКЛЮЧЕН по умолчанию (`SLOT_SPECULATE=0`) и включать его не рекомендуется:
   - он решает слоты впереди заранее, включая вопросы судье. Вопрос, который упреждение задало, а настоящий цикл не задал, оплачен впустую;
   - он делит с настоящим циклом квоты источников, и израсходованная им квота может поменять кучу настоящего слота.

   Упреждающий ПОИСК (`SLOT_PREFETCH=1`) включён и выбор не меняет.

4. **RTX 4090 и RTX 6000 Ada.**
   - **Сессии NVENC.** У GeForce (4090) драйвер держит не больше 8 одновременных сессий кодера на систему. У RTX 6000 Ada лимита сессий нет. Рендер считает сессии сам: свободной нет — клип кодируется x264. Если на машине кодирует что-то ещё, задайте `NVENC_MAX_SESSIONS` меньше 8.
   - **Декодер видеокарты** (`HW_DECODE=auto`) снимает с процессора декодирование клипов в финальной склейке — только для форматов, которые декодировались бит в бит как на процессоре.
   - **Память.** Веса: Qwen3-VL-Embedding-8B 15.2 ГиБ + Reranker-2B 4.0 ГиБ, плюс CLIP эстетики, модель глубины и сессии NVENC. Перед загрузкой рендер сверяет СВОБОДНУЮ видеопамять (веса + 2.5 ГиБ запаса) и при нехватке отказывает с числами — закройте другие программы на карте. Нехватку посреди прогона модель переживает повторами с паузами до ~17 с (сессии NVENC держат память, пока идёт клип); если нехватка стойкая, рендер останавливается перед следующим слотом, а не пропускает кадры без проверки, и перезапуск продолжает с кэша. На RTX 6000 Ada (48 ГБ) места хватает с запасом.
   - **Две видеокарты.** Если их две, реранкер сам уезжает на вторую и считает параллельно с эмбеддингом на первой (`ML_RERANK_GPU=0` оставит всё на первой).
   - **Что остаётся на процессоре.** Фильтры клипа (наезд, грейд, зерно) и финальное кодирование x264 medium: перенос на видеокарту менял бы сами пиксели или давал худшее качество на тот же размер.

## 6.5. Видеокарта только на время задачи (Runpod, посекундно)

Своей карты нет — задачу можно отправить на Runpod так, что карта существует ровно на время задачи:

```bash
python scripts/runpod_job.py --plan    # цены и наличие, ничего не создаёт
python scripts/runpod_job.py --upload . \
    --cmd "pip install -q -r requirements.txt torchvision && python scripts/calibrate_vision.py" \
    --fetch assets/calibration --fetch docs/quality
```

Скрипт создаёт под на самой дешёвой свободной карте community от 24 ГБ (`--gpu` задаёт свой список), загружает папки, запускает команду, показывает её лог, забирает результаты и удаляет под — в любом исходе, включая Ctrl-C и сбой. Удаление проверяется запросом к API.

- **Посекундно.** Поды Runpod тарифицируются посекундно, удалённый под не стоит ничего. Сетевого диска нет (он оплачивается и без пода), поэтому веса моделей (~20 ГБ) скачиваются заново внутри дата-центра, это минуты оплачиваемого времени.
- **Никогда не стоит просто так.** Если эта сторона пропала (закрылась сессия, упала сеть), под удаляет себя сам: через 4 минуты без задачи и обращений (`--idle-min`) и через 4 часа в любом случае (`--max-hours`). Третья страховка — лимит трат аккаунта Runpod.
- **Ключи.** `RUNPOD_API_KEY` — из `.env`, в под не передаётся: у пода свой ключ, ограниченный им самим. Ключи для задачи передаются только поимённо: `--env-from-dotenv LLM_GATEWAY_API_KEY,PEXELS_API_KEY`.
- **Плохой хост не съедает деньги.** Сначала тот же образ проверяется на CPU-поде (доли цента). Хосты со старым драйвером не арендуются (фильтр по версии CUDA). После старта, до загрузки данных, под проверяет видеокарту; не работает — под удаляется, берётся другой хост (до трёх попыток, потолок `--max-usd` на все вместе).
- **Быстрее.** `--prepare "pip install ... && скачивание весов"` идёт на поде параллельно с загрузкой данных отсюда; `--cmd` ждёт и то, и другое.
- **Оплачивается жизнь пода целиком.** Это старт образа, скачивание весов, сама задача и ожидание сети внутри задачи (судья, источники). Между задачами карты нет вовсе.

## 7. Запуск

Как обычно: `python scripts/render_episode.py videos/NN_название`. В начале лога появится строка:

```
Устройство моделей: cuda (NVIDIA GeForce RTX 4090); зрение: Qwen/Qwen3-VL-Embedding-8B + Qwen/Qwen3-VL-Reranker-2B; кодер клипов: nvenc
```

## Честные пределы

- **Качество Qwen против SigLIP2 не измерено:** в среде, где писалась ветка, видеокарты нет. Первые числа дадут шаг 5 и `cascade_model_eval.py`.
- **Кэши.** Ключи кэшей и подпись отбора включают модель: первый прогон заново посчитает каскад и заново выберет кадры. Ответы судьи берутся из его кэша.
- **Полка** (`shelf_index.py`), собранная SigLIP2, не читается — её нужно пересобрать.

## Быстрая закачка весов

`python scripts/fetch_weights.py` качает Qwen-эмбеддинг, реранкер и WeMM одновременно (по 8 потоков на модель, hf_transfer): время равно самой долгой модели, а не сумме. Замер пода 29.09: подряд — эмбеддинг 2 мин 21 с, остальные по ~38 с. Для `--prepare` (идёт до загрузки кода) то же самое встроенной командой с `ThreadPoolExecutor` над `snapshot_download`. `HF_TOKEN` в окружении пода снимает ограничение скорости для неавторизованных запросов.

## Запуск на поде: как не быть слепым и не терять минуты (29.09)

- **Вывод виден всегда.** `runpod_job.py` отклоняет `--cmd`/`--prepare` с `| tail`/`| head` (живой прогон шёл 13 минут вслепую). Строки лога получают метку времени этой стороны. В окружение пода всегда кладётся `PYTHONUNBUFFERED=1`.
- **Ход по этапам — `--watch`.** `--watch videos/NN/media_plan/stage_timings.jsonl` печатает новые строки файла с пода каждые 15 секунд.
- **Рабочая папка — `--workdir`.** Папка вне репозитория ложится в `/work/<имя>/`; без `cd` голые пути (`requirements.txt`) не находились, так упали два запуска. Теперь `--workdir <имя>` ставит `cd` перед `--prepare` и `--cmd`, а запуск печатает, куда легла загрузка.
- **Подготовка — `bash scripts/pod_prepare.sh`.** Пакеты (uv вместо pip, `requirements-gpu.txt`), ffmpeg и веса моделей идут одновременно, каждая часть печатает своё время. Код едет на под до старта подготовки, поэтому скрипт доступен сразу.

```bash
python scripts/runpod_job.py --gpu "NVIDIA RTX A6000" --cloud COMMUNITY --min-gb 46 \
  --upload /path/to/stage --workdir stage \
  --prepare "bash scripts/pod_prepare.sh" \
  --cmd "python scripts/pipeline_smart.py videos/NN_название" \
  --watch stage/videos/NN_название/media_plan/stage_timings.jsonl \
  --fetch stage/videos/NN_название/media_plan --dest ./pod_out --max-usd 0.74 --max-hours 1
```

## Пробный прогон с профилем (30.09) — что передавать и что забирать

Команда запуска, которая отвечает на вопрос «куда уходит время», а не только «сколько»:

```
RUNPOD_API_KEY="$(cat ~/.runpod_key)" python scripts/runpod_job.py \
  --gpu "NVIDIA A40" --cloud SECURE --min-gb 46 \
  --upload <папка эпизода> --workdir stage98 --prepare "bash scripts/pod_prepare.sh" \
  --env CASCADE_MODEL=wemm9b --env SHOT_JUDGE=0 --env STAGE_TIMER=1 --env PROFILE_SAMPLER=1 \
  --env-from-dotenv PEXELS_API_KEY,PIXABAY_API_KEY,OPENVERSE_CLIENT_ID,OPENVERSE_CLIENT_SECRET \
  --cmd "mkdir -p videos/E/media_plan; (nvidia-smi --query-gpu=timestamp,memory.used,memory.total,utilization.gpu,utilization.memory,encoder.stats.sessionCount --format=csv -l 1 > videos/E/media_plan/gpu_usage.csv 2>&1 &); python -u scripts/pipeline_smart.py videos/E; python scripts/shotlist_contact.py videos/E; python scripts/encoder_ab.py --out videos/E/media_plan/encoder_ab.json" \
  --watch stage98/videos/E/media_plan/stage_timings.jsonl \
  --fetch stage98/videos/E/media_plan --dest ./pod_out --max-usd <цена часа карты> --max-hours 1
```

- `--env` (несекретные переменные) видны и подготовке, и задаче: `fetch_weights.py` скачивает WeMM только когда её позовут (`CASCADE_MODEL=wemm9b` и работающий судья).
- **Кэши ответов едут на под и возвращаются (30.09, `--no-persist-caches` выключает).** На под уезжают и после прогона забираются обратно в папку отправки:
  - кэши источников: Commons, музеи, Openverse, поиск стоков эпизода;
  - кэши судьи, отсева по подписям, сгенерированных кадров, планировщика и паспорта;
  - эмбеддинги каскада, реранкера и эстетики.

  Следующий под начинает с них: не платит судье за уже заданные вопросы и не считает превью заново. Ключи всех этих кэшей — содержимое (модель, адрес превью, байты картинки, текст вопроса), поэтому ответ из кэша тот же, что посчитался бы. Эмбеддинги видеокарты лежат под своим ключом, числа процессора на поде не используются.

  Скачанные кадры и клипы (`pexels_cache`, `pexels_video_cache`, `clip_*.mp4`) не едут. Если папки кэша на поде нет, это не ошибка и на код завершения не влияет.
- **Забирается только `media_plan`**: контактные листы (`shotlist_contact_*.jpg`), профиль стеков и `gpu_usage.csv` должны быть внутри него, иначе после удаления пода их не будет. Кадры и `final.mp4` (сотни МБ) не забираются.
- `encoder_ab.py` меряет NVENC против x264 на этой же карте (размер, SSIM, PSNR, время) — вердикт «не хуже» решает владелец по числам.
- Каждый запуск — в свой файл лога (`> pod_probeN.log`): повторный запуск в тот же файл перезаписывает историю подов и трат.
- Ключ Runpod — в файле вне репозитория с правами 600, не в командной строке и не `grep` из переписки.
- Ответ Runpod «Something went wrong» не означает «нет карты»: под мог создаться; скрипт теперь ищет его по имени и берёт (раньше мог создать второй).
- Потолок `--max-usd` — общая сумма на запуск; исчерпан — результат забирается (код 124), затем под удаляется. Ставьте не меньше цены часа карты.
- Фоновые запросы упреждающего поиска и отбора не запускают паузы источников и не занимают очередь глубже одного интервала: настоящий цикл ведёт себя так же, как без упреждения (кроме общих ограничений самих сервисов: квота Pexels 200/час и лимиты IP).
